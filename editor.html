Help

        

          

            Responsive Layout controls how each widget changes position and size
            when the project is built for panels with different viewport
            dimensions. The saved widget coordinates remain the base design;
            responsive settings describe how those coordinates adapt for each
            target panel.
          

          
Start with a base panel

          

            Choose the panel you want to design around—typically a TSW-1070 with
            its effective CH5 viewport of 1280 × 800. Place and resize widgets
            normally on this base layout, then choose how each widget behaves on
            wider or taller targets.
          

          
Responsive modes

          

            
Fixed

            

              Keeps the widget’s original size. Use it for logos, small
              indicators, and controls that must remain an exact size.
            

            
Anchors

            

              Preserve the distance to the selected panel edge. Left/Top,
              Right/Top, Left/Bottom, and Right/Bottom anchors keep controls
              attached to the corresponding corner.
            

            
Center

            

              Keeps the widget centered on the selected axis. This is useful for
              dialogs, loading indicators, central controls, and page titles.
            

            
Stretch

            

              Anchoring to both opposing edges changes the widget size with the
              panel. Left + Right stretches its width; Top + Bottom stretches
              its height.
            

            
Proportional

            

              Scales the widget’s position and dimensions according to the base
              and target viewport ratios. Use carefully because controls and
              text can become unnecessarily large.
            

          

          
Recommended pattern

          
    
            
  • Anchor navigation to the left.
    • 
            
  • 
              Stretch headers and footers between the left and right edges.
            
    • 
            
  • Anchor status information to the upper-right.
    • 
            
  • Center dialogs and loading indicators.
    • 
            
  • Stretch lists, camera feeds, and large content containers.
    • 
            
  • 
              Keep frequently touched buttons at a consistent physical size.
            
    • 
          

          
Testing and panel overrides

          

            Switch Target panel, use Fit panel, and inspect every intended
            target. Preview confirms the exported result. Save a panel-specific
            layout when anchors cannot adapt a design cleanly—for example, when
            navigation orientation, column count, spacing, or dialog size must
            differ on one panel.
          

        

        

          
Timeline Editor

          

            The Timeline Editor controls how a widget visually animates. You can
            add multiple animation tracks to the same widget and configure:
          

          
    
            
  • Trigger: press, release, page entry, or delayed start
    • 
            
  • Animation: fade, slide, scale, glow, press state, or shake
    • 
            
  • Start delay and duration
    • 
            
  • Direction for slide animations
    • 
            
  • Easing, which controls how the animation accelerates
    • 
            
  • Multiple overlapping or sequential animation tracks
    • 
          

          

            Example: when a page opens, a button can slide in
            from the left while simultaneously fading and glowing.
          

          
Action Editor

          

            The Action Editor controls what the project does when an event
            occurs. It is for behavior and logic rather than appearance. Actions
            can be triggered by press, release, hold, page entry, timer, or
            digital, analog, and serial signal changes.
          

          
An action can:

          
    
            
  • Navigate to another page
    • 
            
  • Show or hide a widget
    • 
            
  • Enable, disable, or select a widget
    • 
            
  • Change displayed text or a property
    • 
            
  • Start another widget’s animation
    • 
            
  • Publish a digital, analog, or serial signal
    • 
            
  • 
              Run immediately, after a delay, or sequentially after earlier
              actions
            
    • 
            
  • Run conditionally based on a signal’s value
    • 
          

          

            Example: pressing a Shutdown button could publish a
            digital signal, disable other controls, show a “Shutting Down…”
            message, animate a progress widget, and navigate to a standby page
            after five seconds.
          

          

            In short:
Timeline Editor:
            how a widget moves or visually changes.
Action Editor:
            what happens when an event occurs.
          

          

            Both are saved in the project and included in Preview, exported
            HTML, and CH5Z builds.

            all three.

1. Getting started

            
    
              
  1. Choose File → New project and select Blank or an editable starter.
    2. 
              
  2. Select the intended Target panel before laying out the interface.
    3. 
              
  3. Add pages, then drag components from the left library onto the panel.
    4. 
              
  4. Edit appearance and behavior in the right Inspector.
    5. 
              
  5. Assign Contract names or joins under Signal bindings.
    6. 
              
  6. Save the `.cuiproj`, Preview it, run Health Check, then build the CH5Z.
    7. 
            

            
Recommended base target: design touch-panel projects at the effective CH5 viewport, such as 1280 × 800 for the TSW-1070/1080 family. The physical display resolution is not the same as the application viewport.

          


          

            
2. Editor layout

            

              
Left sidebar
Component library, assets, reusable designs, page templates, themes, page list, and page settings.

              
Center panel
The active page. Drag, resize, multi-select, zoom, and right-click widgets here.

              
Right Inspector
Position, size, z-index, appearance, component properties, signals, responsive rules, timelines, and actions.

              
Top menus
File operations, editing, Preview/Signals, project validation, deployment, diagnostics, and Help.

            

            
Resize either sidebar by dragging its divider. Use the panel zoom controls or Fit panel to see the complete target without changing exported coordinates.

          


          

            
3. Pages and navigation

            
Add, rename, duplicate, reorder, or delete pages in the Page section. Each page can have its own background color/image, transition, size, and external selection signal.

            
    
              
  • Local navigation: select a widget and choose a destination page. No processor programming is required.
    • 
              
  • Contract selection: assign the page’s digital Contract signal.
    • 
              
  • Join selection: assign a digital feedback join.
    • 
              
  • Global widgets: reusable elements can remain visible across pages with page-specific visibility overrides.
    • 
            

            
The page display name determines the namespace used by automatically generated widget contracts. Changing the page-selection contract does not rename its child widget namespace.

          


          

            
4. Adding and editing widgets

            
Drag a component from the categorized library. Select it to edit its local text, colors, glow, assets, text/icon size, position, dimensions, z-index, and component-specific options.

            
    
              
  • Right-click for copy/paste, lock/unlock, align, layer, grouping, reusable symbols, and component simulation.
    • 
              
  • Use Edit → Preferences to show or hide built-in and custom components in the palette without deleting them or affecting placed widgets.
    • 
              
  • Use a blank text field when a button or item should display no label.
    • 
              
  • Use Standard and Selected state options for state-specific text, icons, backgrounds, and assets.
    • 
              
  • Keep enough content inset around strong glows so effects are not visually clipped.
    • 
              
  • Use Undo/Redo or the visible History list to reverse project edits.
    • 
            

          


          

            
5. Signals, joins, and Contracts

            
Each signal binding has one overall mode: Contract or Join. Contract is the default. The project follows these standard names:

            
SignalDirectionStandard attribute

              
DigitalWidget → processorPress

              
DigitalProcessor → widgetSelected

              
AnalogWidget → processorValueSet

              
AnalogProcessor → widgetFeedback

              
SerialWidget → processorText

              
SerialProcessor → widgetLabel

            

            
Open View → Signals to search, find uses, inspect the page/widget tree, rename all uses, allocate joins, generate contract names, preview the exact SIMPL hierarchy, compare `.cce`/`.cse2j` files, or export a signal schedule.

            
Repeated widgets use zero-based item indexing. Their configured/default item count controls how many Contract Editor instances are generated—not the component’s maximum capacity.

          


          

            
6. Responsive and multi-panel layouts

            
Design the base target first. Then configure each widget’s anchors and scale behavior. Use View → Responsive compare for side-by-side layouts, missing-override highlighting, copying between similar panels, breakpoint families, and batch Fit/Validate.

            
Prefer fixed-size touch controls, edge anchors for navigation/status, stretch for lists and video containers, and center anchoring for dialogs. Use explicit target overrides only when the layout structure genuinely differs.

          


          

            
7. Preview, simulation, timelines, and actions

            
    
              
  • Preview: runs the exported interface locally for visual and interaction checks.
    • 
              
  • Simulate: drives digital, analog, and serial feedback without SIMPL and captures widget output events.
    • 
              
  • Timeline Editor: controls visual animation such as fade, slide, scale, glow, press state, and shake.
    • 
              
  • Action Editor: performs navigation, visibility, selection, properties, animation, or signal publishing in response to events.
    • 
            

            
CH5 Desktop and a physical panel remain required for final processor-communication testing.

          


          

            
8. Assets, backgrounds, and custom fonts

            
Import images, audio, video, WOFF/WOFF2, TTF, or OTF files through Assets. Imported assets become immediately available to widget graphics, Standard/Selected state artwork, and page backgrounds.

            
Large embedded assets increase project memory, startup time, build time, and deployment size. Review Project → Panel performance before deployment.

          


          

            
9. Component Workbench, packages, and reusable designs

            
File → Create component opens one Workbench for imported HTML/CSS/JavaScript, blank authored components, starter templates, installed components, and `.cuicomponent` packages. Handwritten source remains authoritative; Composer stores generated adapter behavior separately.

            
    
              
  1. Imported setup: review detected parts, editable properties, states, repeated collections, and Crestron connections. Remove anything the component does not need.
    2. 
              
  2. Add capabilities & edit code: name Component Parts with stable CSS selectors, add Inspector properties or signal mappings, and review HTML, CSS, JavaScript, and Generated Adapter tabs.
    3. 
              
  3. Test & create: simulate typed feedback, outputs, press/release/cancel/hold, states, and modes. Fix blocking findings, then record CH5 Desktop and TSW verification after physical testing.
    4. 
            

            
Common walkthroughs

            

              
Button with Press
Name the clickable surface as a Part, add a Digital Output connection using Press, then use the pointer simulator to verify TRUE/FALSE pulse activity.

              
Selected toggle
Add Standard and Selected states, map the authored checked/class state, and add a Digital Input named Selected. State simulation should move in both directions without replacing authored transitions.

              
Serial label
Name the label Part, add a Serial Input using Label, send normal and empty strings in the simulator, and confirm empty feedback preserves the configured fallback when intended.

              
Analog gauge or slider
Map an Analog Input to Value/Feedback with a 0–65535 range. For an interactive slider also add an Analog Output using Value Set; a read-only gauge needs only feedback.

              
Repeated list
Name the container and item-template Parts, set the zero-based default/max count, then add per-item Press, Selected, Name, and optional analog ranges. Test at least two Widget List instances.

              
JavaScript-generated parts
Open the live preview and allow the authored script to create its controls. Composer observes the preview and adds newly created elements to the Component Map. If a part is still missing, use Pick part from preview, click the exact visible element, give it a meaningful name, then map properties or Crestron connections to that named Part. Retest after a page remount so the generated element and its mapping are recreated reliably.

            

            
Original versus Composer troubleshooting

            
ViewWhat it meansUse it when…

              
OriginalThe imported or handwritten HTML/CSS/JavaScript before Composer-generated adapters are applied.You need to confirm whether a visual, animation, selector, or interaction existed in the authored source.

              
ComposerThe same source with enabled editable properties, Crestron connections, state mappings, repeated-item behavior, and compatibility adapters.You need to verify what will run after placement, Preview, export, remount, or processor feedback.

            

            
    
              
  • If Original is correct and Composer is wrong, inspect the exact generated property, connection, state, or adapter mapping; do not rewrite the authored effect first.
    • 
              
  • If both are wrong, correct the HTML/CSS/JavaScript source or restore the original import and begin again.
    • 
              
  • If a mapped part highlights nothing, repair its selector in the Component Map or repick the visible element from Preview.
    • 
              
  • If Preview works but exported runtime fails, open the exact Test & Create finding and verify local assets, global IDs, browser APIs, instance cleanup, and the saved definition fingerprint.
    • 
              
  • If feedback disappears after navigation, rerun the remount test and confirm the connection is an input from Crestron rather than local-only state.
    • 
            

            
Portability: a created component is saved permanently in the machine-wide Composer library and is also embedded in projects that use it. Export one component as `.cuicomponent` or the complete installed collection as `.cuicomponents`; both formats include Workbench mappings, authored source, generated adapter, states, repeated definitions, acceptance evidence, and referenced embedded assets.

            
Older packages: package versions 1–3 remain supported. When an older package has no current Workbench schema, Composer migrates its legacy properties, behaviors, signals, states, and repeated settings into named Workbench mappings. Import never replaces an installed component without confirmation.

            
Migrating components made with the earlier Workbench

            
    
              
  1. Import the old `.cuicomponent` or open the project containing it; keep the automatic backup.
    2. 
              
  2. Open Component Workbench and confirm every migrated Component Part highlights the intended visible element.
    3. 
              
  3. Review properties, connections, states/modes, and repeated collections for unresolved or duplicate mappings.
    4. 
              
  4. Compare Original and Composer views to ensure authored animations and shape changes were preserved.
    5. 
              
  5. Run Test & Create, including two instances, remount feedback, responsive sizes, and Widget List when supported.
    6. 
              
  6. Export a new package only after validation passes; retain the older package until CH5 Desktop and TSW testing are complete.
    7. 
            

            
    
              
  • Reusable designs: create a master whose instances update together while allowing selected property and signal overrides.
    • 
              
  • Subpages: turn a source page into a linked header, footer, sidebar, or overlay master. Configure its cropped size, placement, excluded pages, and optional Visibility signal; editing the source master updates every deployed instance.
    • 
              
  • Design libraries: export/import versioned `.cuilibrary` project designs. Component libraries use `.cuicomponents` and do not replace built-in widgets.
    • 
            

          


          

            
10. Building and deploying

            
    
              
  1. Save the project and run Health check.
    2. 
              
  2. For Contracts, export/open the `.cce` in CH5 Contract Editor and compile its `.cse2j` mapping.
    3. 
              
  3. Choose Project → Build Project, select target panels, and provide the populated `.cse2j` when requested.
    4. 
              
  4. Inspect the CH5Z before deployment. Confirm index, CrComLib, Web XPanel runtime, worker, contract mapping, target, and viewport.
    5. 
              
  5. Deploy using a saved panel profile. The terminal requests credentials and remains open with the complete result.
    6. 
            

            
Deployment History records package, device, result, log, and backup. A verified successful package can be selected or rolled back later.

          


          

            
11. Validation, performance, and recovery

            
    
              
  • Health check: detects project, signal, asset, navigation, layout, custom-runtime, panel, usability, and performance problems.
    • 
              
  • Panel performance: provides target-aware recommended/caution/high guidance. Scores compare static complexity; they are not measured FPS.
    • 
              
  • Acceptance test: stores Editor, Preview, CH5 Desktop, panel, package, and Contract Editor evidence with the project.
    • 
              
  • Release readiness: requires health, contracts, acceptance, performance, current build provenance, and verified deployment.
    • 
              
  • Recovery: rotating integrity-checked snapshots protect unsaved work and can be browsed by timestamp.

12. Troubleshooting checklist

            

              
CH5 Desktop loads but has no signals
Confirm the same populated contract mapping was used, set the processor/IP ID in CH5 Desktop, and verify the processor login prompt appears.

              
Panel rejects the CH5Z
Run package inspection, verify the selected target supports CH5, and confirm `contract.cse2j` is populated rather than empty.

              
Widget differs in Preview
Run Health Check and Export/Build Self-Test; inspect custom-component runtime errors and missing assets.

              
Multi-device signals do not work
Confirm zero-based item contracts and ensure the configured default count matches the Contract Editor/SIMPL instances.

              
Interface feels slow
Open Panel Performance, reduce simultaneous animation and strong filters, optimize assets, and test on the lowest-powered supported panel.

              
Work was lost after a crash
Open Project → Backups or accept the startup recovery prompt. Do not overwrite the known-good save until integrity validation passes.
